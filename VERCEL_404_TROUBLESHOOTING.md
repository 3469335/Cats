# Диагностика ошибки 404 NOT_FOUND на Vercel

## Текущая ситуация

✅ Локальная сборка проходит успешно  
❌ На Vercel выдается ошибка: `404: NOT_FOUND`

## Возможные причины

### 1. Проверка логов сборки на Vercel

**Как проверить:**
1. Откройте Vercel Dashboard → Ваш проект
2. Перейдите в **Deployments**
3. Выберите последний деплой
4. Откройте вкладку **Build Logs**

**Что искать:**
- ✅ Сборка должна завершиться с `✓ Compiled successfully`
- ❌ Если есть ошибки - они покажут причину проблемы

### 2. Проверка Runtime Logs (Function Logs)

**Как проверить:**
1. В деталях деплоя откройте вкладку **Functions** или **Runtime Logs**
2. Попробуйте открыть сайт
3. Посмотрите логи в реальном времени

**Что искать:**
- Ошибки подключения к БД
- Ошибки рендеринга страницы
- Конкретные сообщения об ошибках

### 3. Проверка настроек проекта

**Settings → General:**
- **Framework Preset:** Должно быть `Next.js`
- **Root Directory:** Должно быть `.` (точка) или пусто
- **Build Command:** Должно быть пусто (используется из package.json)
- **Output Directory:** Должно быть пусто

### 4. Проверка переменных окружения

**Settings → Environment Variables:**
- **DATABASE_URL** должна быть добавлена
- Должна быть включена для **Production**
- Формат: `postgresql://user:password@host/database?sslmode=require`

### 5. Типичные причины 404 на Vercel

#### А) Ошибка при рендеринге страницы

Если страница падает с ошибкой при рендеринге (например, ошибка подключения к БД без обработки), Vercel может вернуть 404.

**Проверка:**
- Откройте Runtime Logs
- Посмотрите ошибки при запросе к странице

**Решение:**
- Убедитесь, что все ошибки обработаны в коде (try/catch)
- Проверьте, что DATABASE_URL правильно настроен

#### Б) Неправильный Framework Preset

Если Framework Preset не `Next.js`, Vercel может неправильно обрабатывать маршруты.

**Решение:**
- В настройках проекта измените Framework Preset на `Next.js`
- Пересоберите проект (Redeploy)

#### В) Проблема с путями импорта

Если пути импорта (`@/lib/prisma`) не резолвятся правильно.

**Проверка:**
- В логах сборки должны быть ошибки TypeScript
- Локально сборка проходит успешно

**Решение:**
- Убедитесь, что `tsconfig.json` правильно настроен
- Проверьте, что пути в `tsconfig.json` совпадают с путями в коде

#### Г) Проблема с Prisma Client

Если Prisma Client не сгенерирован на Vercel.

**Проверка:**
- В логах сборки должна быть строка `Running "prisma generate"`
- После этого должна быть строка `Generated Prisma Client`

**Решение:**
- Убедитесь, что в `package.json` есть `"postinstall": "prisma generate"`
- Убедитесь, что скрипт `build` содержит `prisma generate && next build`

#### Д) Проблема с подключением к БД

Если при рендеринге страница пытается подключиться к БД, но DATABASE_URL неправильный или БД недоступна.

**Проверка:**
- В Runtime Logs должны быть ошибки подключения к БД
- Ошибки типа `Can't reach database server` или `Connection refused`

**Решение:**
- Проверьте DATABASE_URL в Environment Variables
- Убедитесь, что строка подключения правильная
- Проверьте, что БД доступна из интернета (для Neon это должно работать)

## Пошаговая диагностика

### Шаг 1: Проверьте логи сборки
```
Vercel Dashboard → Deployments → Последний деплой → Build Logs
```
Убедитесь, что сборка прошла успешно.

### Шаг 2: Проверьте Runtime Logs
```
Vercel Dashboard → Deployments → Последний деплой → Functions/Runtime Logs
```
Откройте сайт и посмотрите логи в реальном времени.

### Шаг 3: Проверьте настройки проекта
```
Vercel Dashboard → Settings → General
```
Убедитесь, что Framework Preset = `Next.js`

### Шаг 4: Проверьте переменные окружения
```
Vercel Dashboard → Settings → Environment Variables
```
Убедитесь, что DATABASE_URL добавлена и включена для Production.

### Шаг 5: Попробуйте упростить страницу

Если проблема сохраняется, попробуйте временно упростить `app/page.tsx`:

```tsx
export default async function Home() {
  return (
    <div>
      <h1>Test Page</h1>
      <p>If you see this, the page is working!</p>
    </div>
  )
}
```

Если упрощенная версия работает, проблема в подключении к БД или обработке данных.

## Что делать дальше?

1. **Скопируйте логи** из Build Logs и Runtime Logs
2. **Проверьте настройки** по чеклисту выше
3. **Попробуйте упростить страницу** для диагностики
4. **Пересоберите проект** после изменений

## Контакты для помощи

Если проблема сохраняется после всех проверок, пришлите:
- Скриншот/текст Build Logs
- Скриншот/текст Runtime Logs (при открытии страницы)
- Текущие настройки Framework Preset и Build Command
