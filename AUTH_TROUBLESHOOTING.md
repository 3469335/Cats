# Диагностика проблем с аутентификацией

## Что проверено и исправлено:

### 1. ✅ Middleware обновлен
- Добавлена проверка, что `/login` не блокируется
- Добавлен редирект авторизованных пользователей с `/login` на `/dashboard`

### 2. ✅ Callbacks в auth.ts обновлены
- Обновлен `session` callback для работы с NextAuth v5
- Добавлен `jwt` callback для сохранения user ID

## Как проверить работу аутентификации:

### 1. Проверка конфигурации
Откройте: `http://localhost:3000/api/auth/check-config`

Должен вернуться JSON с `status: "ok"` и `allSet: true`

### 2. Проверка страницы входа
Откройте: `http://localhost:3000/login`

Должна открыться страница с кнопкой "Войти через Google"

### 3. Проверка защищенных маршрутов
Откройте: `http://localhost:3000/dashboard`

Если не авторизован - должен перенаправить на `/login`
Если авторизован - должен показать dashboard

### 4. Проверка сессии
Откройте: `http://localhost:3000/api/auth/session`

Должен вернуть информацию о текущей сессии или `null` если не авторизован

## Типичные проблемы:

### Проблема: Не могу войти через Google

**Решение:**
1. Проверьте, что в Google Console добавлен redirect URI:
   ```
   http://localhost:3000/api/auth/callback/google
   ```
2. Убедитесь, что OAuth consent screen настроен
3. Если приложение в статусе "Testing" - добавьте ваш email в Test users

### Проблема: После входа перенаправляет обратно на /login

**Причина:** Сессия не сохраняется или callback не работает

**Решение:**
1. Проверьте `AUTH_SECRET` в `.env`
2. Проверьте подключение к базе данных (`DATABASE_URL`)
3. Убедитесь, что таблицы `users`, `accounts`, `sessions` существуют в БД
4. Выполните: `npm run db:push` для применения схемы

### Проблема: Ошибка "Configuration"

**Причина:** Не установлены `GOOGLE_CLIENT_ID` или `GOOGLE_CLIENT_SECRET`

**Решение:**
1. Проверьте `.env` файл
2. Перезапустите сервер после изменения `.env`
3. Проверьте endpoint `/api/auth/check-config`

### Проблема: Ошибка подключения к БД при входе

**Причина:** `DATABASE_URL` не установлен или недоступен

**Решение:**
1. Проверьте `DATABASE_URL` в `.env`
2. Используйте pooler версию для Neon: `postgresql://...pooler.aws.neon.tech/...`
3. Проверьте endpoint `/api/view-db/health`

## Проверка базы данных:

### Проверьте, что таблицы созданы:
```bash
npm run db:push
```

### Проверьте подключение:
Откройте: `http://localhost:3000/api/view-db/health`

## Перезапуск после изменений:

После изменения `.env` или конфигурации:
1. Остановите сервер (Ctrl+C)
2. Запустите снова: `npm run dev`
